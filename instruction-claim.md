The Industry Standard: Structured Proof
A standard, professional claim process forces the user to give structured data so the Admin can verify it like a checklist, rather than reading a paragraph.

Since this modal is specifically for an Apple MacBook Pro M2 (an electronic device), here is exactly what fields should realistically be inside this form instead of that one big text box:

1. The "Must-Have" Identifiers (Electronics specific)
Replace the big text area with specific, targeted input fields:

Device Name / Username: <Input placeholder="e.g., John's MacBook Pro" /> (Admins can just open the lid and look at the login screen).

Lock Screen Wallpaper: <Input placeholder="Describe the image on the lock screen" /> (Instant visual verification).

Serial Number / MAC Address (Optional): <Input placeholder="Enter if known" /> (If they have this, it's an automatic 100% verified match).

2. The Physical Identifiers
External Case / Color: <Select> dropdown (e.g., Space Gray, Silver, Hard Shell Case).

Distinctive Features: <Textarea> (Keep this, but make it smaller. Label it: "Specific stickers, scratches, or dents").

3. The Logistics (User Info)
Student / Staff ID Number: (Keep this! This was a great idea we discussed earlier).

Contact Phone Number: <Input type="tel" /> (Because if they lost their laptop, checking their email might be difficult right now).

Why this is the "Standard"
If an Admin is looking at two identical Silver MacBook Pros in the physical "Lost" bin, your current text box forces them to guess based on a student's paragraph.

With structured inputs, the Admin's screen will literally show a checklist:

[ ] Login Name: John's MacBook

[ ] Wallpaper: Golden Retriever

[ ] Stickers: Skateboard logo on the bottom right.

The Admin opens the laptop, checks those three exact things, clicks "Approve," and moves on.
